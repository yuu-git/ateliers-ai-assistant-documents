# 通知の閲覧終了と既読化

2026-10-30。未読一覧で開いた記事が既読条件によって一覧から消え、詳細の選択も解除される不具合を修正した。Phase 5 の情報源追加とは独立した Desktop の動作修正で、RSS / Atom・GitHub Releases の両方に適用する。

## 既読にするタイミング

一覧の記事を明示的に開いても、閲覧中は未読のまま保持する。その記事の閲覧を次の操作で終えた時に既読を保存する。

- 別の記事を開く、または選択を解除する。
- 表示条件・タグ条件・情報源を切り替える。
- 狭幅の「通知一覧へ戻る」、巡回履歴へ切り替える。
- 別のメイン画面へ移動する、または通常終了する。

初期選択・プログラムによる選択だけでは自動既読化を予約しない。定期更新、スクロール、ブックマーク、タグ追加・解除、ウィンドウのフォーカス移動だけでは閲覧を終了しない。強制終了・クラッシュ時の未確定操作は保証しない。

## 閲覧中の記事の表示

詳細に表示している記事の行を、テーマに応じたアクセント色の枠と薄い背景で強調する。文字や行は追加せず、選択前後で行の高さを変えない。既読・未読やブックマークとは独立した表示で、キーボードフォーカスが詳細へ移っても維持する。記事の切替で強調対象も切り替え、詳細を閉じると解除する。一覧の条件から外れた記事については、詳細を保持しても一覧へ行を追加することはしない。

## 明示的な既読・未読の優先

詳細の「未読／既読を切替」は、その場で保存する。明示的に「未読に戻す」を指定した場合、その閲覧中の自動既読化は解除し、詳細を閉じても未読を維持する。次に一覧から改めて開いて閲覧を終えた場合は通常の自動既読化を予約する。同じ閲覧中に同じ記事を押し直すだけでは、明示指定を取り消さない。

未読一覧で明示的に既読へ変更すると記事は一覧から外れるが、詳細は閉じる操作まで保持する。ブックマーク解除で現在の一覧条件から外れた場合も同様。自分の操作で記事を削除した場合は詳細をクリアし、削除した記事への既読要求を送らない。キャンセル・削除失敗では既読化しない。

## 実装と整合性

- `WebMonitoringViewModel.Notifications.cs` で明示的に開いた記事の閲覧状態を管理し、閲覧終了した記事の更新を既存 API で直列に保存する。
- 連続選択や他のメタデータ操作中も、現在閲覧中の記事を誤って既読化せず、終了した記事の要求を順番に処理する。
- 失敗は既読扱いにせず、未読のままエラーを表示する。成功した場合に一覧・未読総数・情報源別件数を再取得する。
- 表示更新が進行中の場合はその完了を共有して待ち、古い表示条件の結果で新しい選択を上書きしない。変更のない Markdown とスクロールは維持する。
- 通常画面では、非表示の旧通知一覧の双方向選択バインドを切り離す。旧一覧の項目削除が現行の選択へ伝播して詳細を消す経路を除去した。
- `MainWindow` と `WebMonitoringView` は画面遷移・戻る・履歴切替・通常終了を ViewModel へ伝える。HTTP 通信は既存サービス層のままで、DB・Worker API・スキーマ・通知 ID は変更しない。
