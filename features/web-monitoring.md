# Web 情報収集

## 目的

興味のあるニュース、ソフトウェアのリリースノート、Factorio MOD 更新情報を自動・手動で収集し、変更点を AI が要約して Markdown と通知フィードに残す。

## 情報源

- RSS / Atom: ニュース、技術ブログ。
- GitHub Releases / API: OSS のリリース・変更履歴。
- 一般 Web ページ: RSS/API がない場合。必要時のみブラウザ自動化を検討。
- Factorio MOD Portal 等の固有 API: MOD のバージョン・互換性・更新内容。

取得方法は `IContentSource` のような契約で拡張可能にする。情報源ごとの ID、更新日時、ETag、Last-Modified、ハッシュなど利用可能な手段で差分判定する。

## パイプライン

```text
スケジュール / 手動実行
  -> 取得 -> 正規化 -> 重複・変更検出
  -> 変更内容の保存 -> LLM 要約・分類
  -> 構造化結果の検証 -> Markdown 出力
  -> 通知保存 -> UI への配信
```

## 設定

情報源名、URL/識別子、取得方式、カテゴリ、巡回周期、ON/OFF、最終成功日時、実行状態などを管理する。1時間間隔は例であり、情報源ごとに設定可能とする。手動実行と自動実行は同じユースケースを呼ぶ。

将来の [AI 管理コンソール構想](ai-management-console-concept.md) でも、通常 UI と同じ Application Service の操作を利用する候補としている。先に通常の設定・実行を成立させ、自然言語からの操作やツール基盤は MVP に含めない。構想上の「監視テーマ」と情報源設定の対応は未決定であり、現時点の設定仕様へ追加しない。

## 巡回時の注意

- 毎回全文を LLM に渡さず、追加・変更された項目を優先する。
- API レート制限、タイムアウト、リトライ、条件付き GET を考慮する。
- 重複ニュースを異なる情報源から収集した場合の統合は後続課題。
- 重要度・破壊的変更は LLM の参考判定と明示的なリリース情報を分ける。
- 取得失敗と「新着なし」を区別して記録する。
- 原文・引用の保存と公開は権利や利用規約を考慮する。

## MVP

最初は RSS 1 件を手動取得し、前回との重複を検出し、新着を Ollama で要約して Markdown に保存する。次に SQLite、通知、スケジュール、情報源追加へ進む。
