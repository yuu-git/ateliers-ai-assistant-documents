# Ollama モデル管理

Phase 3 の追加: `IModelWorkCoordinator` により手動 Web 収集全体を既存チャット・モデル操作と直列化する。収集中は記事間も含めモデルを停止・変更できない。収集で使用したモデルも追跡して通常終了時の限定解放に含める。並行利用の参照数管理は導入しない。以下の Phase 1 の記述は導入時の背景であり、現在の詳細は [Web 収集の実装状況](web-monitoring-implementation-status.md) を参照する。

Phase 2 前の MVP として、Desktop が単一チャット用モデルのライフサイクルを管理する。Windows Service、SQLite、モデルのダウンロード・削除・更新、Ollama サーバープロセスの起動・停止は対象外。

## 操作と表示

- チャット画面に「起動」「停止」を表示する。起動は `POST /api/chat` に空の `messages`、`keep_alive: -1`、`stream: false` を送り、停止は同じ形式で `keep_alive: 0` とする。
- 通常のチャット送信にも `keep_alive: -1` を付け、アプリが管理中の保持方針を一致させる。送信時に未ロードなら Ollama によってロードされる。
- 操作後は `GET /api/ps` で状態を確認する。HTTP 成功だけでロード済み／停止済みと決めない。状態不明時には状態未確認／取得失敗を表示し、起動・停止を無効にして一覧更新を促す。
- 「モデル管理」は Ollama 全体のロード中モデル一覧を表示する。モデル名、モデルサイズ、VRAM 使用量、量子化形式、ロード期限を表示し、手動更新と選択行の停止に対応する。空の一覧は空状態として表示する。
- モデル管理画面の手動停止は任意のロード済みモデルに適用する。他アプリにも影響する操作であることを画面に示す。
- チャット中は両画面のモデル操作を禁止する。モデル操作・モデル切替・チャット生成は Application の共通サービスで排他制御し、ViewModel の有効・無効だけに依存しない。

## 管理対象と切替

- `/api/ps` のモデル一覧は自動的に管理対象にしない。明示的なロード要求またはチャット使用要求を送ったモデル名を、そのアプリ起動中の管理対象として追跡する。
- 応答喪失や中止後にサーバーにロード済みの可能性があるため、要求直前に追跡する。操作が失敗した対象も終了処理で確認できるよう追跡を残す。
- モデル選択を変更すると、旧モデルが管理対象の場合だけ停止する。新モデルは自動ロードしない。会話の内容は引き継ぐ。
- 切替中は送信・モデル操作を禁止する。停止に失敗しても選択は新モデルに移し、エラーを表示する。旧モデルは管理対象に残し、モデル管理画面での手動停止または終了時の再試行対象にする。
- 一覧の更新で選択モデルが消えた場合も、旧モデルが管理対象なら停止を試みる。単なる一覧更新で選択を維持できる場合は停止しない。

## 通常終了

- `AppWindow.Closing` でクローズを一度キャンセルし、UI 操作を止めて、実行中のチャット・モデル操作をキャンセルする。
- 共通サービスの排他を待ち、管理対象のうち `/api/ps` でロード済みと確認できたモデルだけを停止する。未使用・未管理のモデルは停止しない。
- サービス全体の終了期限は 5 秒。Window 側にも 6 秒の待機上限を置き、失敗・通信待ちを理由に終了を妨げない。`Closed` イベントでの非同期処理完了には依存しない。
- 失敗は `Trace` に記録する。強制終了・クラッシュ時のアンロード、期限内に応答しないサーバー側処理の完了は保証しない。

## 責務の分離

- `IModelControlService`: 外部サービスのロード状態取得・ロード・アンロードのポート。
- `IModelLifecycleService` / `ChatModelSession`: 管理対象の追跡、排他、状態共有、切替時の解放、期限付き終了処理。UI・HTTP に依存しない Application の処理。
- `OllamaChatService`: 既存の HTTP アダプターに `/api/ps` と空メッセージによる操作を追加。通信 DTO とソース生成 JSON メタデータを Infrastructure に閉じ込める。
- `ChatViewModel` / `ModelManagementViewModel`: 共有サービスを利用し、状態変更を UI スレッドへ反映する。表示用の単位・日付変換は `LoadedModelViewModel` が担当する。
- `MainWindow`: ナビゲーションと非同期終了のホスト処理。HTTP の所有権は引き続き `App` が持つ。

## 運用上の制約と将来

Ollama API からロード元のアプリを識別できない。このアプリが使用したモデルを別アプリも使用している場合、切替・終了時の停止は別アプリにも影響し得る。同じモデルの共有利用は運用で調整する。ロード保持時間は他クライアントの要求や Ollama のメモリ管理によって変わり得る。

これは Phase 1 の単一チャット用方針であり、将来、情報収集・画面監視が同じモデルを使用しているのにチャットの選択変更だけで停止する仕様にはしない。複数機能の利用権・参照数・停止条件は、その機能や Windows Service の導入時に再設計する。今回の `ChatModelSession` をそのまま全機能共通の所有権管理と見なさない。

API 参照: [ロード中モデル一覧](https://docs.ollama.com/api/ps)、[チャットと keep_alive](https://docs.ollama.com/api/chat)。
