# チャットへの画像貼り付け

将来の画面監視に先立ち、Ollama の画像入力を手動で確認するための MVP。画像認識の正確さやモデル能力の自動判定は対象外。

## 操作

- 入力欄にフォーカスして Ctrl+V を押すと、クリップボードの Bitmap 形式の画像を添付する。テキストのみの場合は TextBox の従来の貼り付け動作を維持する。
- 入力欄付近にプレビューと縮小後のサイズを表示し、「画像を削除」で送信前に削除できる。1メッセージ1枚で、貼り直しは既存添付を置き換える。
- テキストと画像、または画像だけを送信できる。送信後は入力側のプレビューを消し、会話内に送信画像を表示する。
- 画像の読み取り・縮小中はチャット入力・送信・チャット側のモデル操作を無効にする。終了時には進行中の処理をキャンセルする。
- 読み取りやプレビューの失敗は入力付近に表示する。変換失敗時には既存の添付を維持し、操作可能な状態へ戻す。
- クリップボードへのアクセスは `Paste` イベントから必ず UI キューへ延期し、順番に処理する。テキストもこの経路で選択範囲へ挿入し、カーソル・改行・Undo・最大文字数を維持する。読み取り待ち中に入力や選択範囲が変わった場合は、遅れて届いた内容で上書きせず通知する。

## データと通信

- `Core.ChatImage` は PNG の Base64、画素サイズ、バイト数のみを持つ不変のメモリ内データ。WinUI、クリップボード、BitmapImage 等に依存しない。
- `ChatMessage` の省略可能な `Image` に画像を保持する。Markdown の `Content` は変更しない。
- Infrastructure の `/api/chat` アダプターが画像を `messages[].images` の Base64 配列に変換する。Data URL の接頭辞は API へ送らない。画像なしの場合は `images` を省略する。1メッセージ当たり配列要素は1件まで。
- 完了した送受信の画像は後続リクエストの履歴にも含める。中止・失敗したターンは画像を含め画面に残すが、既存方針どおりその送受信を次回の送信履歴から除外する。
- モデル変更では画像も含め会話を引き継ぐ。画像非対応モデルへの変更後にエラーになる場合は「新しい会話」でリセットする。添付と会話はアプリ終了時に破棄し、画像ファイルや DB へ保存しない。
- モデル能力は調べず、Ollama が返したエラー本文を HTTP ステータスとともに表示する。エラー本文は長さを制限し、プレーンテキストとして扱う。

## 縮小と表示

- Desktop の Windows Imaging API でデコードし、縦横比を保って長辺1536px以下に縮小する。小さい画像は拡大せず、PNG に正規化する。
- 貼り付け元は32 MiB以下・4000万画素以下、正規化後の PNG は12 MiB以下とする。極端に大きい入力や読み取れない形式はエラーにする。
- Native の入力プレビューは Desktop の責務とし、ViewModel は UI 非依存の `ChatImage` だけを扱う。
- 会話表示は既存の WebView2 1インスタンスを維持する。添付だけを専用フィールドの PNG Data URL として渡し、JavaScript が `<img>` 要素の `src` に設定する。画像を HTML 文字列へ埋め込まない。
- CSP の画像ソースは `data:` のみに変更する。Markdown 由来の画像・生 HTML・外部画像は従来どおり HtmlSanitizer で除外し、外部リソース要求も引き続き禁止する。

## 制約

- メッセージごとの画像は制限するが、会話全体の画像数は制限しない。会話が長くなるとメモリと再送信量、モデルの解析負荷が増える。必要に応じて「新しい会話」を使う。
- 対象はクリップボードの Bitmap 形式。ファイルのコピー、HTML に含まれる画像、ドラッグ＆ドロップ、複数添付、画像編集、OCR 専用処理は対象外。
- 原文フォールバック表示では画像サイズを示すテキストを表示し、会話画像の描画は WebView2 が利用可能な場合に行う。
- 画像付きリクエストの許容枚数や解析結果はモデルと Ollama に依存する。アプリ側では自動判定・自動削除・自動的な画像履歴の切り詰めを行わない。

API 参照: [Ollama ChatMessage の images](https://github.com/ollama/ollama/blob/main/docs/openapi.yaml)、[Windows のクリップボード API](https://learn.microsoft.com/en-us/windows/apps/develop/communication/copy-and-paste)。

## 貼り付け時のクラッシュ対策（2026-10-28）

実機で発生した2件のクラッシュは、いずれも `Microsoft.UI.Xaml.dll` の stowed exception（`0xc000027b`、内部 HRESULT `0x8000ffff`）だった。以前の実装はテキストのみの場合も `TextBox.Paste` 内で同期的に `Clipboard.GetContent()` を呼んでおり、[WinUI の既知の再入問題 #6754](https://github.com/microsoft/microsoft-ui-xaml/issues/6754) と整合する。ただし、取得できたダンプから正確なネイティブ呼び出しスタックを復元できておらず、原因の完全な断定や全再発要因の解消を保証するものではない。

イベント内での形式判定を廃止し、`DispatcherQueue.TryEnqueue` で毎回延期する。すでに UI スレッド上であっても同期実行する近道は使わない。例外の握りつぶしや XAML 全体の未処理例外抑止は行わない。貼り付け要求は直列化し、破棄後のキュー実行・プレビュー更新を防ぐ。

Debug 実画面検証に、選択範囲の置換・改行・カーソル・Undo・最大文字数、テキスト50回と画像5回のキュー投入、画像／テキスト20回の交互貼り付け、遅延データ提供元からの上書き防止、破棄直前の貼り付けを追加。クリップボード読み取りがすべてネイティブの Paste 呼び出しから戻った後であることも検証する。`tests/Verify-ImagePaste.ps1` で実行でき、テスト終了時に元のクリップボードを復元する。

修正後は実画面検証を5回実行し、合計500回のクリップボード読み取りでクラッシュなし（最終版は1回104読み取り）。クリップボードの復元、既存26シナリオ、Markdown の実 WebView2 検証も成功した。x64 の Debug / Release と通常のソリューションビルドは警告0・エラー0。実画面の自動検証は Unpackaged / Debug で行い、MSIX 版の Ctrl+V 実操作やすべてのクリップボード提供元を網羅するものではない。
