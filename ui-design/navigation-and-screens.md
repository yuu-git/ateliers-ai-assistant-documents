# ナビゲーションと画面構成

## トップレベル

| グループ | 項目 | 主目的 |
|---|---|---|
| 機能 | 通知・情報収集 | 新着通知、記事要約、チャンネル別閲覧 |
| 機能 | AI チャット | モデル動作確認・会話 |
| システム・管理 | モデル管理 | Ollama モデルのロード状態確認・管理 |
| システム・管理 | ログ | アプリケーション／システムログの閲覧・コピー |
| システム・管理 | 設定 | Worker、バックグラウンド AI、データ保存先など |

トップレベル項目の**名称変更は表示名に限定**し、既存のページ・ルーティング・ナビゲーション ID を不用意に壊さない。既存のナビゲーションコンポーネント（例：NavigationView）のグループ見出し/区切り/フッター機能を優先する。

## Web 情報収集の内部構造

2026-10-30 の調整で、情報源ナビゲーションの上へ「表示（すべて／未読のみ／ブックマークのみ）」を追加した。区切り線の下へ従来の情報源を配置し、表示条件と情報源は独立して組み合わせる。中幅・狭幅では両者の選択欄を同じ領域に並べ、展開操作なしで切り替える。検索範囲・保存・画面遷移は維持する。

```text
通知・情報収集
├─ 通知（初期表示）
│  ├─ 情報源/チャンネル選択（すべて・個別）
│  ├─ 通知一覧（新しい順）
│  └─ 記事詳細・Markdown 要約
├─ 巡回履歴（タブまたはサブビュー）
└─ 管理（設定/メニュー/ダイアログ）
   ├─ 情報源 URL・巡回周期・自動 ON/OFF
   ├─ 手動巡回
   └─ 記事をまとめて削除（既存の確認を維持）
```

- 初期表示は通知一覧。情報源を選択すると対応する記事のみを表示する。
- 元の参考画像にある「AI ニュース」「.NET / C#」「Factorio MOD」などは **例示**。実際の情報源名を動的に表示する。現状の情報源が1件でも破綻しないこと。
- 「巡回完了・新規0件」は **巡回履歴**で確認できることを基本とする。既存通知として登録されるイベントがある場合のみ通知側にも表示し、履歴と混同しない。
- 通知と記事は概念上異なる。既存の保存モデル/関連付けを尊重する。
- 記事の詳細を見ているときに、通知一覧へ戻れる明確な導線を設ける。
- 手動巡回は画面上の主要操作として残す。Worker が停止中なら理由と復旧導線を示す。

通知管理の追加改修では一覧に初回取得日の見出しと未読表示、独立したブックマーク操作を追加した。フィルターと記事操作は展開領域にまとめ、詳細からタグの追加・解除・絞込を行う。ナビゲーション下部の固定領域には Worker／AI の実状態と Debug/Release を表示し、設定画面と同じコマンドで開始・停止・AI即時一時停止を行う。ポーリングは既存約5秒を共有する。検索範囲・移行・API は [通知管理の実装状況](../features/notification-management-implementation-status.md) を参照する。

## 設定の内部構造

1. **Worker**: 接続/稼働状態、起動・停止、設定再読込、サインイン時自動起動。
2. **バックグラウンド AI**: 要約モデル、AI 処理の一時停止、モデルの自動ロード/アンロード、保存・再読込。
3. **データと保存先**: 記事の単体削除前の確認（即時保存・初期ON）、Debug/Release 表示、Roaming/Local/DB/ログのパス、エクスプローラーで開く。単体削除確認の省略は一括削除に適用しない。

設定はセクション/カード/タブのいずれでもよいが、**一つの長い無区分フォームに戻さない**。保存操作のスコープ（何が保存されるか）を明確にする。既存の操作タイミング・確認・エラー表示を保持する。

## 画面遷移とウィンドウ幅

- 横長: 左のトップナビ + 情報源ペイン + 通知リスト/詳細。
- 中幅: 情報源ペインを折りたたむか切替可能にし、通知本文の可読幅を確保。
- 狭幅: 1列表示にフォールバックし、設定の入力/ボタンが切れないこと。
- 詳細表示は横長ならペイン、狭い画面なら別表示/戻る操作でも可。実装負荷と既存構造を見て Codex が提案する。
