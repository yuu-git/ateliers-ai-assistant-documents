# Phase 7 Codex 実装指示 — 継続画面監視・AI コメント MVP

## 0. 目的と進め方

Ateliers AI Assistant の Phase 7 を実装する。**ユーザーが明示的に選択したウィンドウまたはディスプレイを、設定間隔でキャプチャし、Ollama Vision によるコメントをチャット形式で受信できること**を初期 MVP の完了条件とする。ゲーム（Factorio / FF14）だけでなく、VS Code などの一般アプリケーションも対象とする。コメントの正確性や高度なイベント検出は今回の合否条件にしない。

**最初に既存コードと最新ドキュメントを調査し、実装計画・未決定事項・影響範囲を報告して承認を待つこと。承認前にコードを変更しない。** 本指示と実装済み仕様が矛盾する場合は、現状を提示して確認する。

## 1. 事前調査

- 最新 `roadmap.md`、画面監視関連文書、Phase 6 実装・検証資料、Temp 管理文書 `temp-management.md`、Worker / AI / 通知の設計資料を読む。
- WinUI 3 の画面キャプチャ（Windows Graphics Capture）、対象選択と再利用の可否、画面閉鎖・最小化・保護コンテンツ・ゲーム描画時の制約を実コードと実機で調べる。
- UI / Worker のプロセス構成、ユーザーセッション、UI を閉じた後の Worker 稼働、Ollama 呼び出しと AI 一時停止、モデル自動ロード・アンロード、既存のログと設定を確認する。
- `CapturedImageStore` のセッション／対象 ID、近傍時刻選択、一括リース、上限（64枚/セッション、5分、128 MiB）、`TempFileStore` の所有者分離と非共有契約を確認する。画像は Phase 6 と同様メモリ優先。
- 既存の AI チャットと Markdown レンダラーを再利用できる範囲、データ永続化が必要かを調べる。

## 2. 最初に決定・報告するアーキテクチャ

**キャプチャ実行主体を先に確定する。** Phase 6 のキャプチャが UI 内で成立していることと、UI を閉じても Worker が稼働することは、Worker が同じ API で継続キャプチャできることを保証しない。次の候補を比較する。

1. 既存 Worker が同一ユーザーの対話セッションでキャプチャから Vision 解析まで担当する。
2. ユーザーセッション内の専用 Capture Agent がキャプチャを担当し、Worker と連携する。
3. UI が開いている間だけ監視する暫定構成（UI 終了後の継続を満たさない場合は MVP 制約として明示し、独断で完了扱いにしない）。

選択基準：Windows Graphics Capture の実行条件、対象の再利用・再選択、プロセス間画像転送の必要性、既存 Worker のライフサイクル、保守性、リソース負荷、ユーザーの明示的な許可。**既存 Temp 管理はプロセス間の画像共有を提供しない**ため、別プロセスに分けるなら IPC 契約と転送量・所有権・キャンセルを明示する。必要性がなければ新規 Agent を増やさない。

UI を閉じた後も監視を続けることを目標とする。ただし OS / キャプチャ API の制約が判明した場合は、再選択が必要な条件と代替案を報告し、仕様確定の承認を得る。Windows サービスやログオン前の画面監視は要求しない。

## 3. Phase 7 の機能要件

### 3.1 監視対象・セッション

- ユーザー操作でウィンドウまたはディスプレイを選択し、監視開始・停止・再開できる。許可なく他の対象へ切り替えない。
- セッション ID と対象 ID を維持し、対象消失・権限喪失・セッションロック・取得失敗を明示する。対象が変わった場合、以前の画像を混ぜない。
- 同時監視はまず **1対象・1セッション** を基本とする。複数同時監視は対象外。
- アプリの UI に監視中／停止中／一時停止／エラー、対象、最終キャプチャ時刻、最終解析時刻を表示する。
- 監視開始は必ずユーザーの明示操作。アプリ起動時の自動監視や無断再開はしない。

### 3.2 間隔とジョブ制御

- 監視間隔はユーザー設定可能。**初期値60秒**、候補 10 / 30 / 60 / 120 / 300秒を基本案とし、実測と既存設定設計に合わせて提案する。10秒は保証値ではない。
- キャプチャ周期と AI 解析周期は内部的に分離できる設計にする。MVP は同一周期でもよい。
- AI 解析は原則1件ずつ。前回が処理中なら次回をスキップ／集約し、無制限のキューを作らない。停止時にはキャンセルを伝播する。
- 既存の AI 一時停止・モデル管理・リソース制御を尊重する。AI が停止中、対象が消失、モデルが利用不可のときは安全にスキップ／エラー表示する。
- モデルの処理時間・キャプチャ時間・スキップ回数・エラーを、プライバシーを侵害しない範囲で診断できるようにする。

### 3.3 Vision コメント

- Phase 6 の画像解析基盤を再利用し、定期取得した画像を Ollama Vision 対応モデルに渡して日本語コメントを生成する。
- プロンプトはユーザーが編集可能。初期プロンプトは「画面で確認できる内容を簡潔に述べ、必要に応じて軽い助言・雑談をする。断定できないことは推測と明示する」程度とする。
- 解析結果は時刻付きの**チャット／タイムライン形式**で順次表示。新しいコメントで過去コメントを上書きしない。Slack / Teams 風の見通しのよい UI を目指すが、外観の過剰な作り込みはしない。
- 同じ内容の繰り返しやコメント精度の最適化は今回必須としない。最低限、空応答・失敗・キャンセルは通常コメントと区別する。
- コメント履歴の永続化は既存会話 DB の設計を調査し、採否を提案してから決める。監視画像そのものは原則永続保存しない。

### 3.4 複数時点の画像

- Temp 基盤が提供する同一セッション・対象の時系列画像、一括リース、近傍選択を利用可能な構造にする。
- 例：60秒前／30秒前／現在の画像を使った比較。**今回の MVP は現在画像1枚によるコメント生成で成立**する。複数画像の Ollama 送信を実装する場合は、モデル／API の実対応、画像順序、トークン・メモリ負荷、失敗時の扱いを先に調査し、承認を得る。固定の3枚送信を必須にしない。
- 画像が不足する場合は別セッションや別対象の画像で補完しない。リースは処理終了・中止・例外で確実に解放する。

## 4. UI・運用・プライバシー

- 既存ナビゲーションと Phase 6 画面を尊重する。Phase 6 の手動キャプチャは引き続き利用可能にする。
- 監視の開始・停止・対象再選択・間隔・モデル・プロンプト・コメント履歴・状態を分かりやすく配置する。既存の WebView2 Markdown 表示を活用できる場合は再利用する。
- 監視が継続していることをユーザーが識別できる状態表示を用意する。UI 終了後に監視が続く場合は終了操作時の意味を明確にする。
- 画像、画面内テキスト、ウィンドウタイトル、プロンプト本文を診断ログへ出さない。監視対象画像の自動ディスク保存は原則行わない。
- キャプチャ対象が機密画面へ変わる可能性、画面ロック、最小化、保護コンテンツの扱いを調査・文書化する。取得不可時に無限リトライや大量ログを発生させない。

## 5. 非対象・スコープ管理

- 音声合成・再生、音声通知、MCP 動画生成、AI 管理コンソール。
- 高度な画像差分検出、意味的イベント認識、ゲーム固有の攻略判定、自動操作、OCR 専用基盤。
- 汎用 Web 監視、AI による情報源自動発見、通知システムの大幅再設計。
- 複数監視対象の同時処理、常時録画・動画保存、画像の無制限蓄積。
- 不要な新規フレームワーク・サービス・DB Migration。必要性がある場合は先に理由と代替案を報告する。

## 6. 検証と完了条件

最低限、次を検証する。

1. 一般ウィンドウとディスプレイで、明示的に選択した対象を継続キャプチャできる。ゲーム画面は可能な範囲で実機検証し、制約を記録する。
2. 60秒などの設定間隔で複数回実行し、時刻付き AI コメントが蓄積する。
3. Vision 応答が監視間隔より長い場合でも解析が重複・無限滞留しない。
4. 停止・再開・対象消失・モデル停止・API 失敗・キャンセル・異常終了時に安全に状態遷移する。
5. UI を閉じた後の監視継続の可否を**実際のプロセスで**確認する。実現できない場合は、完了報告に制約を明示し、ユーザー判断を仰ぐ。
6. Temp 管理の件数・期限・容量・リース保護を破らず、画像が蓄積し続けない。メモリ使用量、解析時間、GPU 負荷を可能な範囲で測定する。
7. Phase 6 手動解析、RSS / GitHub Releases 巡回、通知、AI チャット、UI / Worker の基本動作に回帰がない。
8. Debug / Release ビルド、関連自動テスト、必要な実機テストを実施する。

**Phase 7 完了条件：** ユーザーが選択した対象を設定間隔で継続取得し、Ollama Vision のコメントを時刻付きチャット形式で受信でき、開始・停止と処理負荷の基本制御が機能すること。これにより、情報収集と画面監視の2本柱を備えた Ateliers AI Assistant の初期 MVP 到達とする。
