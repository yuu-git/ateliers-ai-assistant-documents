## ロードマップの変更内容

### Phase 6：画面キャプチャ・Vision 解析 MVP
**目的**：ユーザーが明示的に選択した画面またはウィンドウを手動キャプチャし、ローカル Ollama Vision モデルで解析して結果を表示できるようにする。

**想定スコープ**：
- キャプチャ対象の選択
- 手動キャプチャと画像プレビュー
- 既存 Ollama 画像入力機能を活かした Vision 解析
- 解析結果の表示と基本的なエラー処理
- 将来の継続監視に再利用できる責務分離

**完了条件**：対象選択 → 手動キャプチャ → プレビュー → Vision 解析 → 結果表示の一連の操作が可能であること。

**対象外**：定期キャプチャ、継続監視、AI コメントの自動投稿、音声出力、高度な画像差分検出、長期コンテキスト管理。

### Phase 7：継続画面監視・AI コメント MVP
**目的**：ユーザーが指定した画面・ウィンドウを設定間隔でキャプチャし、ローカル Vision モデルによるコメントをチャット形式で受信できるようにする。ゲームだけでなく一般的なデスクトップ作業も対象となり得るが、特定アプリ専用の高度な助言は必須としない。

**暫定スコープ**：
- 監視対象の指定、開始・停止・再開
- 定期キャプチャと Vision 解析・コメント生成
- Slack / Teams に近い時系列のチャット形式でコメントを表示
- 処理が重なった場合のジョブ制御（無制限に解析を積み上げない）
- 既存の AI 一時停止・資源制御との整合性
- ユーザーが明示的に開始する監視と、監視中であることの可視化

**暫定完了条件**：監視開始後、指定間隔・実際の解析処理能力に応じて画面を取得し、AI コメントをチャット形式で表示でき、停止・再開できること。

**Phase 6 完了後に確定する事項**：キャプチャ API の制約、UI を閉じた際の動作、既存 Worker または別 Capture Agent の採用、最小化・画面ロック・対象消失時の扱い、解析頻度・負荷制御の具体値。Phase 7 の実装指示を作る時点で調査・判断すること。

**対象外**：高度な画像差分・意味的イベント検出、ゲームごとの専用認識、コメント品質の保証、音声生成、画面に基づく外部アプリの自動操作、無制限の会話コンテキスト蓄積。

### マイルストーン：Ateliers AI Assistant 初期 MVP
**Phase 7 完了時点を初期 MVP 到達点とする。**

初期 MVP は次の二本柱を満たすこと：
1. **情報収集**：RSS / Atom と対応 API（まず GitHub Releases）から情報を巡回・収集し、AI 要約を Markdown として保存・確認できる。汎用 Web 全体の自動探索は必須としない。
2. **画面アシスタント**：指定した画面を継続的にキャプチャし、AI が生成したコメントをチャット形式で受信できる。コメントの専門性・正確性や音声化は MVP 合否の必須条件にしない。

### 将来構想（時期未定・フェーズ番号なし）
以下を固定フェーズから外し、既存の構想文書への参照を維持しつつ整理する：
- **音声出力基盤**：画面監視と Web 情報収集の双方で使えるオプションの音声通知・読み上げ
- **AI 管理コンソール MVP**：既存 Application Service を自然言語で安全に操作する機能。Tool Calling、承認、実行履歴等は後日具体化
- **汎用 Web 監視**：任意 Web ページの取得・抽出・差分監視
- **関心に基づく AI 情報発見・推薦**：新しい記事の発見、候補選別、関連度評価、要約
- **Factorio MOD Portal 対応**：専用 API 型情報源の将来候補
- **既存 MCP 動画生成連携**：Markdown から音声付き解説動画を生成する既存資産との連携
- その他、現行ロードマップに記載済みの将来構想は削除せず、矛盾がないよう整理する
